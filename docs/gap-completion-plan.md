# 缺失能力补齐计划

本轮继续完成迁移验收记录中的缺口，书源能力优先。保留现有未提交改动和用户数据，参考 `legado_FU` 只读，不将 Android 专有运行时的名称当作服务端功能完成的证据。

## 实施和写入范围

1. 书源执行：校验关键词、目录格式化和收费状态、文件下载地址、正文元数据、图片和封面解码、购买回调、动态发现和评论。独立子任务负责书源实体、规则引擎、SourceActionController 和回归。
2. 阅读界面：字体、背景、配置方案、范围书签、替换作用范围；新增能力的真实配置和操作页面。独立子任务仅写 `web`。
3. 横向服务：AI 净化、助手与 Skills、MCP、角色语音和统计。独立子任务写新增服务及测试，沿用已有 HTTP、JSON 和认证基础设施。
4. 主任务：注册接口、替换与书签模型、导出规则、版本化备份、独立浏览器执行服务、启动与部署整合，以及最终联测。

## 简化和兼容原则

复用现有用户存储、章节原文缓存和导出器。阅读替换只应用一次，原文缓存不被破坏。浏览器通过独立 Node 服务运行真实页面，与 Java API 和 React 分离。备份使用复制，恢复先检查所有路径和版本后再写入，避免移动活跃文件。

## 回归与验证顺序

修改旧行为前增加规则身份、作用范围、选区边界和备份完整性的回归。先运行对应测试，再统一运行后端完整构建；同一目录不并发运行 Gradle。前端执行类型检查、lint、单元测试与浏览器测试。所有 fixture 写入隔离工作目录，实际用户数据只读核对。

浏览器链路使用本地动态页面验证 JavaScript、Cookie 和页面事件；AI/TTS 用本地兼容协议 fixture 验证请求、缓存和结果，真实外部服务需要用户自己的配置。最后重启独立 API 与前端，重新核对原书架与书源身份，更新能力矩阵为实测状态。

收尾验收补充两项回归：同源 EPUB 的实际选区、范围高亮、跨章恢复及书签定位；书源 SSE 在首次轮询前结束时的交互投递。EPUB 使用真实上传的 XHTML 文件验证字体、背景、简繁转换和阅读统计，并保护安全沙箱。Windows 本地文件路径统一转换为公共 `/epub/` URL，保留章节锚点；生成文件仅写入隔离存储。
