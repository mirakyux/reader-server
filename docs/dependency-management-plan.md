# 复用框架依赖管理

2026-10-09。用户最新澄清：单独声明的直接依赖检查并升级至可用的最新稳定版；可复用的传递依赖由框架／上游管理。此前将独立直接库也降至平台默认版本的处理范围过大，本次纠正。先前逐包 latest 的传递覆盖仍删除。

1. 对照 Spring Boot 4.1.1 官方 BOM，区分日志实际实现与转接组件，以及独立技术栈和纯传递依赖。记录变更前实际依赖图；既有 JSON、书源、HTTP、日志启动和导出回归提供行为保护。
2. 复核独立直接库的最新稳定元数据，恢复 Coroutines、Gson、JsonPath、Guava 的升级版本。Jackson Kotlin 模块也检查最新稳定，核心家族复用该模块的上游版本来源。日志、Netty 及测试辅助库继续复用 Boot／Vert.x／直接库，不重新添加传递覆盖。Kotlin 运行库与编译器保持一致，XPath 的 ANTLR 兼容约束保留。
3. Jackson 保持 3 系列与现有 Vert.x SPI，功能测试不写死补丁版本；验证 JSON 格式、Kotlin 行为、错误处理和旧 Jackson 2 运行模块缺失。检查前端直接声明和兼容限制，删除仅用于追逐 aria-query 最新版的 override，交由 Testing Library 自身声明选择。
4. 执行完整后端测试，再打包；隔离真实书源、阅读、缓存、导出及备份恢复验收。最终图及 JAR核对日志绑定和实际版本，恢复主服务并核对原有书架／书源身份。
5. 前端锁文件变更后运行 lint、typecheck 与既有单元测试。文档明确“直接依赖检查升级，传递依赖复用上游”，不要求每个传递包都为 registry latest。参考 FU 保持只读，不新增业务依赖、不改全局运行时、不提交或推送。
